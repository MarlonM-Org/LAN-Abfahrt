# CLAUDE.md – LAN-Abfahrt

Lokales Party-Spiel: TV-Ansicht (Phaser) + Handys als Controller (Browser), verbunden über Socket.IO mit einem Node-Server im Heimnetz.

## Befehle

- `npm run dev` – Server + Vite-Middleware auf Port 3000 (TV: `/tv.html`, Handy: `/`)
- `npm run typecheck` – TypeScript prüfen (vor jedem Commit)
- `npm run build` / `npm start` – Produktiv-Build
- `npm run online` – Build + Server + Cloudflare-Quick-Tunnel (`server/online.ts`), Freunde spielen über `https://….trycloudflare.com` mit; feste Adresse per `ONLINE_URL`
- `npm run bots -- 4 --game=murder` – Testspieler; `--party` für eine komplette Party (zum Testen neuer Features immer einmal durchlaufen lassen)
- `npm run test:records` – Tests ohne Browser für die ewigen Bestleistungen der Board-Spiele (`server/records.ts`)
- `npm run test:lieder` – Tests ohne Browser für Guess the Song (Genres/Runden, Dateien → Genre, Deezer-Trefferwahl, kompletter Rundenablauf)
- `npm run test:wolfrunde` – Tests ohne Browser für Werwolf mit Erzähler (Stapel-Regeln, Geheimhaltung: TV ohne Karten, jeder nur seine, Erzähler alle; Dieb, Totenkopf, Ergebnis)
- `npm run test:band` – Tests ohne Browser für die Strand-Band (jede Instrumentenspur jedes Songs spielbar und hörbar im Song, Besetzung, Ablauf mit Groove und Band-Bonus)
- `npm run test:maler` – Tests ohne Browser für Montagsmaler live (Wortliste ohne Dubletten, unscharfer Vergleich, Hinweise, Strich-Ops/Schlüsselbild/Neuabgleich, Wort nie im Snapshot, kompletter Ablauf)
- `npm run test:music` – Tests ohne Browser für Tonhöhenerkennung (Einsingen), MIDI-Parser und alle eingebauten Songs (Offline-Rendern: Pegel, Länge, stumme Kanäle, Szenen-Zuordnung); `npm run render:music -- <ordner>` schreibt sie als WAV

## Architektur-Regeln

- **Server ist autoritativ.** Clients senden nur Eingaben; Spiellogik und Zufall leben in `server/`.
- Gemeinsame Konstanten/Geometrie/Typen gehören nach `shared/` (wird von Server, TV und Handy importiert – keine Node- oder DOM-spezifischen Imports dort, außer Canvas-Zeichenfunktionen).
- Zustand geht in zwei Teilen raus (`Room.flush()`): `meta` (`GameMeta` – Spielerliste, Leaderboards, Zähler; nur wenn er sich ändert) und `state` (`GameLive` – Phase, Minispiel-Snapshot); die Clients setzen beides zu `GameState` zusammen. `Room.changed()` sendet sofort, bündelt aber auf höchstens alle 40 ms.
- Neues Minispiel = Klasse in `server/` die `MiniGame` implementiert (siehe `server/minigame.ts`), neuer `MiniKind` + Eintrag in `MINI_INFO` (`shared/games.ts`, inkl. Pflichtfeldern `icon` (Emoji) und `orientation` (`'landscape'` = zwei Daumen wie am Gamepad, `'portrait'` = eine Hand/Sensor/Listen/Text, `'any'` = ein Riesenknopf) und optional `inspiredBy` – Vorbild nur als „à la …“-Untertitel, Spiel nie nach dem Original benennen) + Eintrag in `MINI_HOWTO` (`shared/games.ts`: Ziel-Satz + 2–3 kurze Steuer-Zeilen für die Regelkarte) + in `ARCADE_GROUPS` einsortieren, Zweig in `Room.createMini()` (`startMini()` zeigt vorher die Regelkarte, Phase `intro` – startet erst, wenn alle Verbundenen bereit sind oder VIP/Laptop es erzwingen, nie per Timer), Phaser-Szene in `client/host/` (in `main.ts` registrieren), Screen-Modul in `client/controller/screens/` (in `controller/main.ts` einhängen) und Bot-Verhalten in `scripts/bots.ts`.
- Aufwärmrunde statt Regelkarte für Echtzeit-Controller-Spiele: Kind in `WARMUP_KINDS` (`shared/games.ts`) eintragen. Dann startet `Room.startMini()` in Phase `intro` über denselben Weg (`createMini()`) eine echte Übungsinstanz mit `ctx.practice` (`GameLive.mini` = ihr Snapshot, `intro.warm`, `inGame` = die Übenden, neue `miniSeq` je Instanz → TV-Szene startet neu); TV zeigt die echte Szene + `WarmupScene` (Leiste über dem HUD), das Handy den echten Screen + BEREIT-Leiste (`client/controller/warmup.ts`, `#app` rutscht darunter). Bereit/VIP/Enter wie bei der Karte; dann wird die Übung verworfen, gehaltene Eingaben losgelassen und das echte Spiel frisch gestartet (gleiche Teams über `ctx.warmTeams`, Kart gleiche Strecke). Im Spiel bei `ctx.practice`: kein Rundenende/Zeitlimit (`endsIn` 0)/Schrumpfen, Ausgeschiedene nach `PRACTICE_RESPAWN_MS` wieder rein (Szene muss „wieder lebendig“ zeigen); `finish()` startet still eine frische Übung, `log`/`record` zählen nicht, Wetten sperrt der Raum. Ohne eigenes Respawn startet der Raum nach `PRACTICE_OUT_MS` eine frische Übung, wenn ein Mensch raus ist. Bots sind sofort bereit und stehen in der Übung still. Nicht für rundenbasierte, Quiz-, Abstimmungs-, Geheimrollen- und Board-Spiele.
- Minispiele melden ihr Ende über `ctx.finish({ groups, details, subtitle })` – Münzen/Ergebnis-Screen macht der Raum. Neue Szenen nutzen `Juice`/`sfx` (`client/host/juice.ts`, `client/host/sfx.ts`) statt eigener Partikel/Töne; der 3-2-1-Piep kommt automatisch aus `ui.ts`, Ansagen über `say()` (`client/host/speech.ts`).
- Einzelspiele aus der Lobby (Arcade, Laptop-Auswahl, Einzelspiel-Liste – nicht Spielbrett/Date-Night/Trinkrunde) zählen fürs Leaderboard des Abends (`server/session.ts`, nur im Speicher) und die ewige Tabelle (`server/leaderboard.ts`); im Ergebnis bietet `GameState.nochmal` „Nochmal“ an (Kart: nächste Strecke).
- Laptop-Rechte nur über `isLaptop()` (`server/net.ts`) prüfen, nie über die IP allein: Online-Verbindungen über den Tunnel kommen ebenfalls von localhost und werden an den Proxy-Headern erkannt (`viaProxy()`). Schreibende Endpunkte, die nicht fürs Internet gedacht sind, sperren `viaProxy()`-Anfragen (siehe `server/music.ts`).
- Balance-Board-Spiele (`BALANCE_KINDS` in `shared/balance.ts`): reihum, Grundgerüst `BalanceTurnGame` (`server/balance.ts`: Einmessen, Gewichtsspitzen, Überspringen). Messwerte kommen nur vom Laptop (`bb:sample` → `MiniGame.balance()`, WebHID in `client/host/balanceBoard.ts`, Pfeiltasten/J als Ersatz) bzw. vom Bot selbst (Eingabe `bb`). Nicht in Zufall/Spielbrett/Turnier aufnehmen. Bestleistungen pro Spieler: `ctx.record()`/`ctx.records()` → `server/records.ts` (`data/records.json`, Richtung je Spiel in `RECORD_DIR`); neue Board-Spiele melden ihre Leistung dort und zeigen `state.records` über `RecordPanel`/`recordLine` (`client/host/balanceHud.ts`).
- Geheime Infos nur über `privateFor()` → Event `private`, nie in `GameState`.
- Handy-Ausrichtung: `client/controller/orientation.ts` zeigt Ansage-Karte/Overlay und lockt auf Android – Screens übersteuern bei Bedarf per drittem Tupel-Element (`[key, build, 'any']`). Quer-Spiele bauen auf dem gemeinsamen Querlayout `.lx` (Kopf · `.lx-left` Stick · `.lx-mid` · `.lx-right` Knöpfe, ausgelegt auf 300 px Höhe) und `stickZone()` aus `stick.ts` auf; Halte-Eingaben hören auf `input-reset`, Rückmeldung über `haptic()`.
- Zuschauer: Screens mit `spectate`/`watch`/`dead`/`out`/`over` im Key bekommen automatisch `spectatorBar()` (`client/controller/spectator.ts`: Live-Stand, Emotes, Wetten); Elimination-Spiele liefern dafür `spectator` im Snapshot über ein `BetBook` (`server/spectator.ts`), Emotes laufen zentral über den Raum und das TV-Overlay `client/host/emotes.ts` – keine Szene anfassen.
- Handy-UI: Screens nur neu bauen, wenn sich der Screen-Key ändert (`pickScreen()`), sonst nur Werte updaten – sonst gehen Taps/Wischgesten verloren.
- Phaser-Szenen werden beim Neustart wiederverwendet: Instanzfelder in `create()` zurücksetzen.
- UI-Texte auf Deutsch, Pixel-Look (Font „Press Start 2P“, Welt 480 × 270).
- Guess the Song (`lieder`): Ton nur über `server/liederton.ts` – der TV bekommt pro Runde einen Token (`/api/lieder/ton/…`, nie über den Tunnel), lädt in `prep` vor und meldet `ready`/`error` über `host:mini` → `MiniGame.hostInput()`. Quellen: eingebaute Synth-Songs, eigene Dateien in `data/lieder/<Genre>/`, Deezer-Hörproben nur mit `LIEDER_VORSCHAU=deezer`. Keine Dienste ohne erlaubte API einbauen (Spotify verbietet Quiz-Spiele, YouTube verlangt sichtbaren Player, Amazon hat keine API, iTunes-Previews nicht für Unterhaltung – siehe README).
- Werwolf mit Erzähler (`wolfrunde`): bewusst ohne Spielmechanik – das Spiel lost nur die Karten aus, erzählt und entschieden wird am Tisch (Marlons Wunsch: keine Phasen-Führung, wenig Text). VIP wählt den Erzähler (`vipAction('narrator:<id>')`), Karten nie in `WrState`/am TV (erst am Ende `roles`), jeder bekommt nur seine Karte über `privateFor()`, der Erzähler alle (`book`) samt 💀/↺ pro Spieler.
- Montagsmaler live (`maler`): Wort nur über `privateFor()` (Maler, wer es erraten hat), im Snapshot nur das Muster `hint`. Striche laufen als Ops (`MalerOp`, `shared/maler.ts`): Handy bündelt ~15 Hz mit Zähler `n`, Server führt die Strichliste und schickt im Snapshot nur die Ops der letzten 1,5 s plus gelegentlich ein Schlüsselbild (`ink.full`: alle paar Sekunden, in der Auflösung, auf Anfrage per `host:mini`/Eingabe `sync`); passt der Zähler nicht, holt er per `need` das ganze Bild vom Handy. Der TV malt inkrementell in eine RenderTexture.
- Musik: Song-Format v2 in `shared/music.ts`, eingebaute Loops in `shared/musicBuiltin.ts`, Synth/Sequencer in `client/music/player.ts` (TV **und** Werkstatt `/musik.html` nutzen denselben). Eigene Songs + Szenen-Zuordnung speichert `server/music.ts` unter `data/music/`; Änderungen gehen per `music:songs`/`music:assign` live an die TVs.

## Status-Seite (Claude-Artefakt) – in JEDER Session pflegen

Marlon verfolgt den Projektstand über ein Claude-Artefakt: **https://claude.ai/artifact/8XRwB1H3bsUUTV5g9dAtmi** (slug `3cefa65c-7b4d-4434-a343-b15cb2c458b5`).

- Quelle der Wahrheit ist `docs/status.json` (in Arbeit, Warteschlange, Abgeschlossen mit PR-Nummer, Feedback pro Spiel, allgemeines Feedback). Spieleliste, Icons und „à la …“ kommen automatisch aus `shared/games.ts`.
- Bei jeder Änderung am Stand (Arbeit begonnen, PR gemergt, neues Feedback von Marlon): `docs/status.json` anpassen (`updated` = aktuelle Zeit), `node scripts/status-page.mjs` ausführen und `docs/status.html` als `index.html` per Artefakt-Tool (`publish_files` mit dem slug oben, `base_version` vorher per `get_artifact` holen) neu veröffentlichen. Änderungen an `docs/status.*` mit committen.
- Feedback-Status pro Spiel: `positiv`, `offen`, `in Arbeit`, `umgesetzt` (ohne Eintrag = „noch kein Feedback“).
- Ein Feedback-Eintrag heißt auch „von Marlon getestet“: Die Arcade-Sortierung „Getestet zuerst“ liest genau diese Liste (`server/reviewed.ts` → `GameMeta.reviewed`). Nur eintragen, was Marlon wirklich gespielt/kommentiert hat – neue Spiele bekommen erst mit seinem ersten Feedback einen Eintrag.
